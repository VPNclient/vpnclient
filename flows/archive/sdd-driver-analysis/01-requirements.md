# Requirements: VPN Driver Deep Analysis

> Version: 1.0
> Status: DRAFT
> Last Updated: 2025-12-30

## Problem Statement

Текущий `DRIVERS_ANALYSIS.md` содержит базовый анализ существующих SOCKS-драйверов (HevSocks5, Tun2Socks, SingBox TUN), но не покрывает:

1. **Производительность и benchmarking** - нет количественных метрик сравнения
2. **OpenVPN и WireGuard** - отсутствует анализ традиционных VPN протоколов
3. **ГОСТ VPN** - не исследована интеграция российских криптографических стандартов
4. **Китайские стандарты SM2/SM3/SM4** - нет оценки поддержки китайской криптографии
5. **Кроссплатформенные ограничения** - недостаточно деталей по специфике каждой ОС

**Почему это важно:**
- Расширение на международные рынки (Китай, Россия, СНГ) требует поддержки национальных крипто-стандартов
- OpenVPN/WireGuard — индустриальные стандарты, часто требуемые корпоративными клиентами
- Объективные метрики производительности нужны для выбора оптимального драйвера
- Платформенные ограничения влияют на архитектурные решения

## User Stories

### Primary

**Как разработчик VPN движка**
**Я хочу** иметь детальный сравнительный анализ всех доступных VPN драйверов и протоколов
**Чтобы** принимать обоснованные решения при проектировании архитектуры и выборе технологий

### Secondary

**Как DevOps инженер**
**Я хочу** понимать производительность и ресурсопотребление каждого драйвера
**Чтобы** оптимизировать deployment и масштабирование

**Как продакт-менеджер**
**Я хочу** знать, какие криптографические стандарты поддерживаются
**Чтобы** выходить на рынки с локальными требованиями (Китай, Россия)

**Как архитектор**
**Я хочу** понимать платформенные ограничения каждого решения
**Чтобы** проектировать кроссплатформенную архитектуру без неожиданных блокеров

## Acceptance Criteria

### Must Have

1. **Given** текущий набор драйверов (HevSocks5, Tun2Socks, SingBox TUN)
   **When** проведен benchmark производительности
   **Then** документированы метрики: throughput (Mbps), latency (ms), CPU usage (%), memory (MB), battery impact (Android/iOS)

2. **Given** требование поддержки OpenVPN
   **When** проанализированы доступные библиотеки (OpenVPN3, openvpn-flutter)
   **Then** задокументированы: кроссплатформенность, сложность интеграции, лицензирование, ограничения

3. **Given** требование поддержки WireGuard
   **When** проанализированы доступные библиотеки (wireguard-go, wireguard-android, wireguard-apple)
   **Then** задокументированы: кроссплатформенность, производительность, интеграция с Flutter, ограничения

4. **Given** требование поддержки ГОСТ VPN
   **When** проанализированы библиотеки (flutter_vpn_gost, go-gost, gost-crypto)
   **Then** задокументированы: поддерживаемые стандарты (ГОСТ Р 34.10-2012, ГОСТ Р 34.11-2012), сертификация, интеграция

5. **Given** требование поддержки китайских стандартов SM2/SM3/SM4
   **When** проанализированы библиотеки (gmssl, sm2-sm3 Go packages, SingBox SM support)
   **Then** задокументированы: поддерживаемые алгоритмы, совместимость с китайскими серверами, производительность

6. **Given** необходимость кроссплатформенности
   **When** проанализированы платформенные ограничения
   **Then** создана матрица поддержки (драйвер × платформа × ограничения)

7. **Given** все собранные данные
   **When** проведен сравнительный анализ
   **Then** создана итоговая рекомендация по выбору драйверов для разных сценариев

### Should Have

8. **Given** анализ производительности
   **When** проведено тестирование на реальных устройствах
   **Then** документированы результаты на разных ОС (Android 12+, iOS 15+, Ubuntu 22.04, Windows 11, macOS 13+)

9. **Given** анализ безопасности
   **When** проверены известные уязвимости
   **Then** задокументированы CVE и mitigation strategies для каждого драйвера

10. **Given** анализ лицензирования
    **When** проверены лицензии всех библиотек
    **Then** задокументированы юридические ограничения и требования attribution

### Won't Have (This Iteration)

- Реальная имплементация драйверов (это будет в следующих SDD потоках)
- Тестирование на всех возможных устройствах (фокус на референсных платформах)
- **Создание custom драйвера** - ТОЛЬКО анализ существующих Flutter библиотек
- **Изобретение велосипеда** - использовать готовые open-source решения
- Анализ других криптостандартов (например, южнокорейских ARIA/SEED)
- Коммерческие библиотеки и проприетарные решения
- Legacy протоколы (PPTP, L2TP/IPsec) - фокус на современных стандартах

## Constraints

- **Технические**:
  - Должна сохраняться совместимость с текущей архитектурой flutter_vpn_engine
  - Анализ должен базироваться на документации и open-source кодовой базе

- **Производительность**:
  - Benchmark должны проводиться на одинаковом оборудовании для честного сравнения
  - Минимальные требования: throughput >= 50 Mbps, latency <= 100ms

- **Платформы**:
  - Обязательные: Android 8+, iOS 13+
  - Желательные: Linux (Ubuntu 20.04+), Windows 10+, macOS 11+

- **Зависимости**:
  - Доступ к существующему проекту flutter_vpn_engine
  - Доступ к тестовым VPN серверам для benchmarking
